### 两个协议坑（关键）
1. **上游用 HTTP 200 + `event:error` 表达业务错误**。选错模型时回 200，错误在 SSE `event:error` 里；原样透传表现为**空回复**（`content:""`+`finish_reason:"stop"`）。shim 现在：首事件是 error 且未发头 → 真 502 + 上游原文；流中途出错 → 转成 `data:{"error":…}`。
2. **虚拟模型 `yd-fast`/`yd-ultra` 只在声明 `virtual-models-v1` 时下发**，且不能直接对话（需 `POST /api/models/<id>/resolve` 拿 `{mode,sessionId}`，实测缺 mode 回 `code:4000`）。所以能力头不带它 → 目录只剩 32 个真实模型（31 个 accessible）。

### 档位（与 Qoder 相反）
`reasoning_effort:"off"` 是**真档位**：实测 `off` → `reasoning_tokens=0`，`high`/`max` 有思考 token，`bogus_xyz` 也 200（上游不严校验）。所以 `thinkingLevelMap` 按目录声明直接映射，`off` 不置 `null`。`max_tokens` 到 200000 都被接受。
